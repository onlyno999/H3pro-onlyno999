## 3. 跨段无缝接力与 15s 零重影终剪规则
- **首尾帧精准匹配**：在段与段接力时，将上一段成片的尾帧（如 15.00s / 第 362 帧）提取并注入下段作为首帧垫图，或直接挂入 Node 74 / Node 75 视频通道；
- **FFmpeg 零重影拼接**：
  ```bash
  ffmpeg -y -v error \
    -i P01.mp4 -i P02.mp4 -i P03.mp4 -i master_bgm.wav \
    -filter_complex "
      [0:v]setpts=PTS-STARTPTS[v0];
      [1:v]select='gt(n\,0)',setpts=PTS-STARTPTS[v1];
      [2:v]select='gt(n\,0)',setpts=PTS-STARTPTS[v2];
      [v0][v1][v2]concat=n=3:v=1:a=0[vconcat]" \
    -map "[vconcat]" -c:v libx264 -crf 18 -preset medium final_master.mp4
  ```
- **消灭叠影**：通过 `select='gt(n\,0)'` 剔除第 2 段起的第 0 帧重复垫图帧，实现 100% 电影级无缝连续出片。
- **铁律：双参考接力（防脸型跑偏）**：第 2 段起**必须**同时注入两张参考图，各司其职，缺一不可——
  - `ref_image_0` (Node 18) = **人物定妆照**（锁脸：面部特征、服装穿搭，全片固定同一张）；
  - `ref_image_1` (Node 23) = **上一段尾帧**（锁场景/机位：环境延续、镜头衔接）。
  - 反模式：只用尾帧做 Node 18——尾帧里人脸小/角度偏，几段后脸型必跑偏（2026-10-01 刁哥悬崖片第4/6段近景翻车教训）。
  - 远景段（人物成小点、看不清脸）可只用尾帧；凡近景/中景露脸的段必须双参考。
- **铁律：首中尾三锚接力（用户 2026-10-03 定）**：分段一律 10 秒一段，每段采用**首 / 中 / 尾三张锚点帧**——
  - 第 1 段：首锚、中锚、尾锚取自带人物场景九宫格的预置关键帧；
  - **第 2 段起：首锚 = 截取上一段生成视频的实际尾帧**（必须从已生成成片里抽帧，不许拿预置图、九宫格裁图或想象图冒充）；中锚 = 后面预置的中帧；尾锚 = 预置的最后尾帧；
  - 三锚与双参考（定妆锁脸 + 场景锁定）同时喂齐才许派发，缺一不开拍。

## 4. 台词优化与防乱讲话规范 (Dialogue & Anti-Ramble Guard)

按 MiniMax H3 官方规范执行**动作/语气/台词细化与防乱讲话死锁**：
1. **防乱讲话机制 (Strict Anti-Ramble)**：
   - **台词时间线动作化**：台词严禁单独存在，必须嵌套在具体分镜 `【动作】` 中：
     `【动作】<Subject N> (SN) [动作与具体肢体语言]，[语气/音量/语速描述] 说：<d>[中文] 精确台词原文</d>`
   - **说完全程静止锁定**：台词结束后必须紧跟闭嘴防乱动指令（如：“说完嘴唇抿成一条线，喉结滚一下，把更多话咽回去；不再接话，保持沉默闭唇”），**彻底锁死嘴唇，杜绝模型自由发挥乱叽里咕噜讲话**；
   - **非发声镜头闭嘴死锁**：非台词镜头/听者反应镜，正向强制注入 `mouth naturally closed, lips completely still, not moving along with vocals, no singing or talking`，负向词库强制注入 `singing, mouth open, lip-sync, talking, speaking, vocalizing, open lips`；
2. **情绪靠动作带 (No Adjective Emotions)**：
   - 严禁空洞形容词（不写“他很悲伤地说”）；
   - 必须翻译成具体生理动作与微表情（如：“视线落在凉透的青菜上，右手指节轻敲桌面三下，压着情绪低沉发闷地说”）；
3. **接收先于反应 (Receive Before React)**：
   - 听者先听见、停顿或微动作（如搓烟纸、喉结滚动），再开口说话；
4. **声音与说话人全局绑定**：
   - 角色在 `subject_definitions` 绑定后，在 `声音设定` 明确：
     `<Picture 2> 是说话人用 (S2) 标记，参考音频 2，并在全片保持一致`；
   - 全片台词统一使用 `(S1)/(S2)` 锚定声线，杜绝跨镜头跳音色。

## 6. 纯净画面与杜绝声音乱入铁律规范 (Strict Silent-Action & Foley-Only Iron Law)

### 核心铁律（ABSOLUTE IRONCLAD RULES）
**只要没有指定谁说的话，或没有写对白台词时，生成结果必须且只能是：【画面 + 物理动作拟音/环境音】，绝对没有背景 BGM，绝对零人声对白与零画外旁白！**

**2026-10-01 音频铁律（湖面飞跑实测通过）**：v2.5 工作流三个音频节点全灌静音后，提示词层面必须用**最强硬的禁音乐版**才能锁住模型不生成 BGM。
**铁律**：无对白视频，提示词音频部分固定写法——**中英双语三重禁止**：
> 绝对禁止任何背景音乐、绝对禁止任何乐器声、绝对禁止歌曲旋律，只保留真实环境声音——[具体拟音列表，如：脚尖点水的清脆水花声、水面哗哗声、风声、衣服猎猎声、呼吸声]。no music, no background music, no instruments, no melody, only natural foley sounds.
实测：湖面飞跑 YAMNet 人声 0.01、音乐 0.01，一次通过。每版必过 YAMNet 门禁，干净保留 H3 原声，污染才剥离替换。

### 痛点根源分析
H3 是原生的**音画一体模型**（Video + Audio 同步生成），具有极强的音频生成自主性。当分镜中**没有写台词、没有旁白、也没有指定谁说话**时：
1. 若不进行显式嘴唇与声学封锁，H3 会自动“脑溢”出莫名其妙的女声喘息、呻吟、叽里咕噜对话或画外旁白；
2. 若不强制压制非剧情音乐，H3 会自动混入廉价合成器罐头 BGM，破坏电影级纯净度。

### 彻底执行铁律的五重死锁 (The 5-Layer Iron Lock)

1. **【铁律 1】正向提示词：显式声明【画面+物理拟音，无台词对白，无画外旁白】**
   - 在 `detailed_description` 容器内，每个未指明发声者的镜头必须强制写入：
     `【动作】人物嘴唇自然紧闭，全程完全静止不发声（lips completely still and naturally closed, strictly no speaking, no vocalization, no voiceover, no singing, silent character）。`
   - 在 `【音效】` 中必须 100% 详写**具体动作拟音与环境底噪**，同时写明无对白：
     `【音效】仅有动作物理拟音与环境空间底噪（如：急促粗重呼吸声、衣服摩擦声、脚步踩在地面沙沙声、山风呼啸声）；绝无人物台词对白，无画外旁白，无人声呢喃（strictly no dialogue, no voiceover, no human speech, no phantom vocal）。`

2. **【铁律 2】声音设定区：明确封死非发声状态**
   - 若本分镜没有指定谁说话，在提示词前置区必须显式声明：
     ```text
     声音设定：
     本视频为无对白动作与环境音镜头，全片无指定说话人，无任何对白台词，无画外旁白；仅保留现场物理动作拟音与环境底噪贯穿。
     ```

3. **【铁律 3】背景 BGM 彻底清零 (Zero Background Music)**：
   - 当没有显式要求配乐时，音乐通道必须严格锁死为 `None`：
     `[non_diegetic_music] None. There is no non-diegetic background music in this video track, absolute silence on the music channel to allow clean external master score mixing.`
   - **音乐字段三分支写法（2026-10-03 用户给的参考代码定版）**：编译提示词时按「音乐风格」的值分支处理，只允许这三种写法——
     - 含「不指定」→ 什么都不写（pass，提示词里不出现音乐行）；
     - 含「禁止音乐」→ 只写这一行结构化声明：`- 背景音乐：禁止任何背景音乐，non_diegetic_music 必须严格输出 "N/A"，不得写任何配乐/旋律/节奏`；
     - 指定了某种风格 → 写 `- 背景音乐风格：<风格名> — <该风格的提示描述>`。
     禁配乐的意思只以「禁止音乐」分支的这一行出现在音乐字段里，正文其他地方不写禁配乐句（与铁律 8 改版一致）。

4. **【铁律 4】负向提示词 (Negative Prompt)：强制死锁 20 项发声与 BGM 抑制词**
   - 必须强力注入负向死锁矩阵：
     `dialogue, speaking, talking, voiceover, narration, monologue, whispering, screaming, female vocal, male vocal, phantom voices, muttering, human voice, mouth moving, parted lips, open mouth, vocalization, background music, noisy score, bgm, humming`

5. **【铁律 5】口型视觉死锁 (Visual Lip Lock)**：
   - 负向压制 `moving mouth, parted lips, talking head, lip flap`；
   - 确保模型即便在人物做大动作时，嘴唇也始终保持自然闭合，从视觉源头彻底掐断触发语音合成的可能。

6. **【铁律 6】旁白隔离与 prompt 尾部三约束（ArcReel #2261/#2264，2026-10-01 定为铁律）**：
   - **根源**：MiniMax H3 是会产音的模型，prompt 里任何像"要说的话"的文本都会被念出来，还会让画面人物对着旁白对口型（ArcReel #2264 实锤：`画外音说` 四个字会被连同旁白一起念出来）。
   - **铁律：旁白文本永不进视频 prompt**——无归属旁白（裸 `{台词}`）在 prompt 渲染期整段丢弃，只保留画面描述；有说话人的 `@[角色]{台词}` 才保留，渲染为 `<角色>说 {台词}`；旁白的唯一交付通道是 TTS 或后期配音。
   - **每条无对白 prompt 末尾强制追加三约束**：
     1. `只保留自然环境音、音效和角色对白声音，禁止任何配乐。`
     2. `保持无字幕，字幕由后期人工添加。`
     3. `画面中的人物不得念旁白、不得对旁白对口型。`
   - **书写规范**：提示词只写纯画面描述 + 拟音清单，不写叙事散文；不出现"画外音说"四个字；旁白如需标注，格式固定为 `旁白：{台词}`（仅用于 TTS 送稿，不进视频 prompt）。

7. **【铁律 7】参考音频关闭定版：三路全灌静音（2026-10-03 用户实测确认，此后不许再议）**：
   - **背景**：ComfyUI 界面里可以对节点设 bypass/mute（仓库 `runninghubService.ts` 的 `buildCustomOfficialUltimateWorkflowJson` 给 Node 38/67/68 设 `mode=2` 即此写法），但那份完整工作流 JSON 只适用于手动导入 ComfyUI；RunningHub 已发布工作流的 API 派发（nodeInfoList）**没有 mode 字段，命令层面传不进旁路**——此路不通，不许再尝试。
   - **唯一定版做法**：凡不使用某路参考音频，该路 LoadAudio 节点（38 人声 / 67 歌声 / 68 三路）一律灌入静音 WAV 顶掉工作流预置样音；无参考音频时三路全灌静音。有参考音频时仅指定一路接参考音频，其余两路照旧灌静音。**静音时长跟本段时长走**：按分段/脚本时长等长生成（派发器按 `--duration` 现生成，44.1kHz 立体声 PCM），不是固定 5 秒——5 秒只是早期 5 秒段的实例（2026-10-03 用户修正定版）。
   - **严禁**：发空值（任务约 40 秒失败）、省略节点不发（预置样音会混进成片）。
   - **效果与验证**：等同于在 UI 里关掉节点——预置样音进不来，模型仍按提示词【音效】自生现场拟音。2026-10-03 五秒实测（v2.5 工作流 2086280720103858177）：YAMNet 人声 0.02 / 音乐 0.03，拟音正常，用户试听确认定版。

8. **【铁律 8】提示词只写需要的：不写死禁配乐/禁旁白（2026-10-03 用户改版，覆盖旧版"写死禁令"做法）**：
   - **只写需要的**：派发提示词通篇只写视频里需要的东西——画面、动作、运镜、【音效】里要出现的声音、被指定说出的台词。配乐、旁白这类不要的东西，**连"禁止……"的写死句也不写**——写死禁令实测不行，等于反过来把概念递给模型。
   - **为什么不用写死**：提示词按本技能规则写好（主体定义清楚、【音效】只列要的声音、谁说话写明白、嘴部状态写清），模型一般就照着执行，不会乱加配乐、不会乱扯旁白；真在成片里检出，按污染处理（音频门禁拦截、重跑或剥离替换）。
   - **零索取不变**：提示词永远不许向模型索要配乐；配乐只能由用户显式提出、走后期外挂。旁白只在脚本明确要求时才存在，且按铁律 6 走 TTS/后期通道，旁白文本不进视频提示词；agent 更不许自作主张给成片加旁白。
   - **连带修订**：铁律 6 尾部三约束中的禁配乐/禁念旁白句、铁律 1【音效】示例里的"绝无……"句，不再作为提示词必写项；【音效】只正面列出要的声音即可。

9. **【铁律 9】只配拟音：严禁按画面自动配乐、严禁自动旁白（2026-10-03 用户严令，铁律 7/8 的总纲加强版）**：
   - **唯一许可**：模型只许根据画面生成与动作、环境一一对应的**现场环境拟音**（风声、水声、脚步声、衣料摩擦、器械与物体碰撞、呼吸等），除此之外不许自加任何声音。
   - **严厉禁止·自动配乐**：严禁模型根据画面内容、氛围或情绪自行生成任何背景音乐、旋律或乐器声——画面再燃、再悲、再壮阔，也不许它"看着画面配乐"（no scoring music to the picture, no automatic background music whatsoever）。
   - **严厉禁止·自动旁白**：严禁模型自行生成旁白、画外音、解说或任何脚本未指定的人声；画面里没人被指定说话，就只有拟音。
   - **拟音白名单（2026-10-03 用户定版）**：提示词双向锁死——①**写什么有什么**：【音效】只写视频画面里真实发生、真实存在的声音，画面里没有的声音一律不许写进提示词；②**有什么写什么的反面同样成立**：成片只许生成提示词【音效】里明确列出的拟音，**没写的一律不生成**——未列的鸟鸣、犬吠、额外环境声、人声、乐器声等，写没写都不许凭空出现。列了哪些，就只有哪些。
   - **执行与判定**：落实不靠在提示词里写禁令（见铁律 8 改版）——【音效】只正面列出要的声音，就是全部声学要求；成片音轨检测出音乐或旁白/人声 = 污染，带病不许交付（重跑或剥离替换后重过门禁）。
   - **落地方式**：本铁律是写给 agent 的执行规则；派发提示词通篇只写需要的内容，禁令句（成段的、短句的）一律不进提示词正文，negative 短语保留为约束字段的既有做法，派发器不自动追加任何禁令文字。

## 7. 长视频全自动化生产 SOP：前置三大资产锁定与后段自动继承调用机制 (Long-Video Asset Pre-Lock & Auto-Inheritance Pipeline)

### 核心生产法则
**制作长视频（多段式短剧/广告长片）：刚拿到剧本，出了提示词之后，第 1 件事就是做人物定妆卡，然后做多宫格场景图，还有物品道具图。前置资产制作完毕后，后续所有分段自动继承并全局调用！**

### 生产流水线四部曲：
1. **第一步：做人物 1:1 定妆卡 (Character Makeup & Identity Lock)**：
   - 提取三视图正面、侧面、半身特写，做 1:1 融光与去影棚灰底处理；
   - 锁定主角/配角五官骨架、发型、肤色与固定服装穿搭，鞋底留地防漂浮；
   - 注入 ComfyUI **Node 18 (`ref_image_0`)** 与 **Node 35 (`ref_image_7`)**，保证全剧所有分段人物绝对同一张脸、穿同一套衣服。

2. **第二步：做场景九宫格锁定 (Scene Nine-Grid Lock)**：
   - **铁律 S：场景一致性九宫格锁定（用户铁律，2026-10-01 焊死）**：不管场景图是用户上传的还是 AI 生成的，拿到第一张图后**必须先做九宫格，不许跳过九宫格直接开拍**。生产顺序铁律：**定妆照（人物锁定）→ 场景九宫格（空间锁定）→ 开拍**。
   - 九宫格锁定四步法——
     ① 先有一张**正面场景图**，把它作为参考图传入；
     ② 写提示词生成 **180 度反打视角**，模板："参考图1生成180度反打视角，背景是…，保持色调、光影、氛围和原图完全一致"（背景描述也可留白，让 AI 自由发挥）；
     ③ 有了正反两张图，场景即被锁死，再把**这两张同时作为参考图**，生成侧视图、俯视图等其他角度；
     - **侧面视角生成模板（用户 2026-10-03 定版，侧视图一律用这条）**："参考图生成完全相同的侧面视角画面：场景的空间大小、墙体结构、建筑布局、所有道具家具的尺寸与摆放位置全部保持不变，仅更换摄像机拍摄角度；人眼正常高度拍摄；合理补充视角遮挡的边角细节、物体侧面结构、墙体衔接关系；画面风格、光影方向、色调质感、材质细节与原图高度统一；不新增物体，不删减结构，不改动布局，不扩大场景；精准透视，空间逻辑真实连贯。"
     ④ 最终拼出**九宫格**（正面/反打/左侧/右侧/俯视/仰视/近景陈设/远景全景/景深纵深），九张视角互相咬合，空间零死角；
   - **九宫格带人物铁律（用户 2026-10-03 定）**：做场景九宫格时，尽量把主角本人（穿本片定妆服装、脸用定妆照锁定）一并放进格子里做参考——人物要出现在关键机位格中，站在其在本片中的实际位置/姿态上（如起点、行进中、终点）。原因：生产采用**首中尾帧锚点、10 秒一段**——每段以首帧/中帧/尾帧锚定人物位置与场景关系，九宫格里预置了带人物的画面，锚点才有据可依、人物与场景不脱节。纯空景九宫格只作兜底，不作首选。
   - **开拍门**：九宫格拼出后必须发用户预览确认，用户确认通过后才允许开拍；未经确认开拍=违规。
   - **铁律 K：转场关键帧预置（用户铁律，2026-10-02）**：10秒长段中段易跑偏，开拍前必须预置所有转场关键场景帧——
     - N段视频，开拍前先定死N-1张转场关键帧（每张明确：场景状态、人物位置、机位角度），转场帧是"目标"不是"结果"；
     - 每段的Node 23一律挂预置的转场关键帧做硬锚点，不许拿"上一段实际尾帧"凑合（实际尾帧可能已跑偏，用它接力=把跑偏传下去）；
     - 第1段：[场景九宫格] → [转场帧1]；第2段：[转场帧1] → [转场帧2]；以此类推，段段有预置锚点；
     - 违者：段间场景跳变即重拍该段。
   - **引用注入铁律**：每次向管线注入参考图（Node 18/23/35/76 等），必须同时携带人物定妆照 + 场景九宫格，缺一不可——定妆照锁脸锁服装，九宫格锁空间锁光影。
   - **换场景铁律**：剧情切换到新场景时，必须按上面四步法为新场景重新生成九宫格并锁定（新九宫格同样发用户预览确认）；新场景开拍后，后续分段的场景引用一律切换为新场景九宫格，旧场景九宫格作废。
   - 锁定环境色温、自然采光方向、空间物理结构与建筑质感，防止换分镜场景发生剧烈漂移；
   - 注入 ComfyUI **Node 23 (`ref_image_1`)** 与 **Node 76 (`ref_image_8`)**，全剧各段统一空间光影。

   - **铁律 T（人物空间占位硬约束）**：见文末独立节【铁律 T：人物空间占位硬约束】，每分镜必执行——此处以独立节为准，不复述。
